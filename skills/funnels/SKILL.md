# Funnels — агент по воронкам

Назначение: превратить фундамент в **карту продаж**, по которой контент-план знает, куда ведёт каждая единица контента. Без `profile/funnels.md` контент-план размечает строки наугад.

Место в цепочке: `foundation` → `offer` → **`funnels`** → `tone-of-voice-builder` → `design-system-builder` → `content-plan`.

## База знаний (читай первой)
`${CLAUDE_PLUGIN_ROOT}/skills/funnels/references/vechnye-voronki.md` — модель воронки, типы, связки, шаблоны точек касания, кейсы, метрики, чек-листы. Разделы 3.4 (паспорт), 6.1 (поля строки плана) и 11 (алгоритм агента) — обязательные.

## Где лежат профили
Профили лежат в папке `profile/` в корне проекта. Этот скилл читает `business-dna.md` (раздел «Актуальный запуск» — главнее всего), `audience.md`, `offer.md`, `hunt-ladder.md`; пишет `profile/funnels.md`. Drive подключён → продублируй по `${CLAUDE_PLUGIN_ROOT}/skills/content-pipeline/references/drive-bridge.md`.

## Шаг 0 — вход
Прочитай профили. Проверь полноту входа по таблице 11.1 базы: ниша и продукты с ценами, смысловая карта ЦА, цель на период, площадки, ресурс контента в неделю. Не хватает — задай не больше 5 вопросов через AskUserQuestion, с вариантами. Отдельно спроси про **события запуска**: даты эфира/марафона/старта потока, кодовые слова под каждое, что уже не используется. Ответы допиши в `business-dna.md` → «Актуальный запуск», если их там нет.

## Шаг 1 — выбор воронок
По таблице 3.3 выбери **1–3 активные воронки** под цель периода. Больше трёх — размывает трафик. Для каждой — тип из каталога 4.1 и готовый рецепт из 4.3.

## Шаг 2 — паспорт каждой воронки (раздел 3.4)
Код вида `F1-СЛОВО`. Поля: сегмент и боль · обещание · вход (форматы и темы) · триггер и CTA · лид-магнит · прогрев по дням (таблица 5.4) · витрина (хайлайт, закрепы) · оффер и цена · дожим · метрики и цели (гипотезы помечай). Кодовое слово — по правилам 4.4: короткое, своё на каждую воронку. Кейсы и цифры клиента не выдумывай: нет доказательства → пометка «нужен кейс».

## Шаг 3 — словарь CTA и кодовых слов
Таблица: слово · воронка · что человек получает · точная фраза CTA (формулы 5.5, голосом из `tone-of-voice.md`, если он уже есть) · где повторяется (экран, голос, подпись).

## Шаг 4 — путь прогрева по дням
Для каждой воронки: день 0 … день 5 — что человек получает и в какой момент. Учитывай 24-часовое окно Meta (10.2): длинные серии переноси в Telegram или email.

## Шаг 5 — точки касания к созданию
Чек-лист с дедлайнами: шапка (5.1) · три закреплённых поста (5.2) · хайлайт (5.3) · бот или DM-серия (5.4). Что уже есть у человека — отметь «есть», остальное — «создать до <дата>».

## Шаг 6 — правила разметки для content-plan
Заверши файл разделом «Разметка строк», который дословно читает `content-plan`:
- баланс функций на неделю по 6.2: охват 35–45% · прогрев 25–35% · продажа 15–20% · удержание/имидж 10–15%;
- ритм недель по 6.3 (проблема → метод → продажа → дожим), привязанный к датам из «Актуальный запуск»;
- у каждой строки плана обязательны поля из 6.1: код воронки · функция · уровень осознанности · CTA точной фразой · точка назначения · кодовое слово · этап прогрева · метрика;
- имиджевого контента без воронки — не больше 20%.

## Шаг 7 — сохрани и проверь
Сохрани `profile/funnels.md` по формату 11.3 (карта → паспорта → словарь → прогрев по дням → точки касания → разметка). Прогони чек-лист 10.3 по каждой воронке. Покажи человеку карту одной строкой на воронку и спроси: «что здесь неправда?». Поправил — обнови файл. Дальше — `tone-of-voice-builder`, `design-system-builder`, `content-plan`.

## Чего не делать
- Не пиши контент и не строй план: это `content-plan`.
- Не предлагай больше трёх воронок разом.
- Не подставляй кейсы из базы как кейсы клиента: они примеры подачи, не бенчмарки.
- Не используй маркетинговый шаблонный язык в CTA: голос клиента из `tone-of-voice.md`.
