# Content Routine — ежедневный автопилот

Две задачи по расписанию, которые превращают контент-план в автономный конвейер.

## Где лежат профили
Профили лежат в папке `profile/` в корне проекта: `profile/business-dna.md`, `profile/audience.md`, `profile/hunt-ladder.md`, `profile/offer.md`, `profile/tone-of-voice.md`, `profile/design-system.md`, плюс паспорт `profile/foundation.html`. Google Drive — необязательное зеркало: коннектор подключён → продублируй туда; нет — работай с `profile/` и не останавливайся. Облачная рутина без доступа к папке проекта читает зеркало в Drive — значит, для автопилота зеркало обязательно.

Готовые промты рутин — `${CLAUDE_PLUGIN_ROOT}/templates/routines/` (карта `00-КАРТА-РУТИН.md`): 01 план на две недели (вс) · 02 медиа в облаке · 03 медиа локально · 04 автопостинг · 05 статус · 06 аналитика · 07 Threads · 08 зеркало в Drive. Горизонт медиа по умолчанию — **7 дней**.

## Утро (напр. 08:00) — генерация на N дней вперёд
1. Прочитай контент-план. Отбери строки на ближайшие N дней (`ГОРИЗОНТ: 7 дней` по умолчанию) без медиа (K пустая).
2. Для каждой сгенерируй контент по её формату: колонка «Формат» = `Карусель · T1–T4 · H/C/K` или `Reels` — используй скиллы `carousel`, `reels` и т.д., `profile/design-system.md` и банк фото.
3. Залей в новую папку Google Drive → впиши ссылку, статус = «Запланировано».
4. Ничего не публикуй.

## Ночь (00:00) — автопостинг + проверка
1. Прочитай план. Если все строки со ссылкой имеют статус «Запланировано»/«Опубликовано» — всё ок (А НЕ ошибка).
2. Для строк «Запланировано» с медиа → скилл `autopost` (Postiz).
3. Отметь «Опубликовано».

## Как поставить
Cron-задачи (локально `~/.claude/scheduled-tasks/` или облачная рутина). Промпт каждой задачи — самодостаточный: `[id Google-таблицы контент-плана]`, `[ссылка на Drive-папку с профилями и фото]`, коннекторы, правила. Человеческий контроль = опционально статус «Утверждено».

Коннекторы: Higgsfield, Composio (Drive/Sheets), Postiz.

## Чтобы локальная рутина не вставала на разрешениях (проверено живым прогоном)
Локальная рутина работает при открытом ноутбуке и **без человека рядом** — любой диалог «Разрешить?» останавливает её до утра. Три правила:

1. **Режим.** Локальная рутина в приложении всегда идёт в режиме Manual — файл настроек папки и режим чата на неё не влияют (проверено). Работает allow-лист из `templates/settings.local.safe.json` в папке, где рутину создали: команды из него проходят молча. Создавай рутины из чата, открытого в папке завода. **Коннекторы в allow-листе должны стоять по реальным id `mcp__<uuid>`, не по названиям** — `setup-check` находит и дописывает их сам. Рутине 03 (монтаж) нужны ещё `npx`, `npm`, `node`, `whisper-cli`, `touch`, `cd`, `rm` из шаблона, иначе HyperFrames встанет на первом вызове.
2. **Команды в промпте рутины — простые.** Никаких `$(date)`, `$(stat …)`, `>` и `>>`, цепочек через `;`. Файлы (отчёт, лог) создавай инструментом записи файлов, а не через shell-редирект. Одна команда — одно действие: `python3 build.py`, `ffmpeg …`, `ffprobe …`. На «хитрую» команду приложение даёт только «Allow once» — запомнить её нельзя, рутина встанет.
3. **Первый запуск — кнопкой «Run now» при человеке.** Всё, что рутина всё-таки спросит (коннекторы claude.ai спрашивают один раз на инструмент), подтверди «Always allow» — ответ сохраняется на задаче и дальше не спрашивается.
4. **Что можно — в облако.** Планирование, тексты, Higgsfield, автопостинг — облачными рутинами claude.ai (нет shell, нет вопросов). Локально — только карусели кодом и монтаж.

Проверка перед сном: запусти рутину вручную и убедись, что она дошла до конца без единого вопроса. Если встала — смотри, какая команда, и упрости её по правилу 2.
